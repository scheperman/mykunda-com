The sprints

Each sprint delivers a working, testable feature set.

1

Search & discovery engine

High priority

Replace the static demo data on search.html, home.html and area pages with real database queries. Make filters, map pins and search results work against live listings.

Connect search.html to Supabase — filters (type, price range, beds, area) build a real query. Results render from DB instead of demo array.
Map integration — real pins from lat/lng in the database. Clicking a pin opens the listing card. Map bounds filter results.
Area pages read from DB — Kololi, Bijilo, Brufut, Cape Point, Sanyang show real listings for that area instead of demo cards.
home.html featured section — pulls the newest verified listings from the DB. "Staff picks" curated via an admin flag.
property.html from DB — load a single listing by UUID from the URL. Photos from Storage. Show real agent info.
Full-text search — add Meilisearch (or Supabase full-text) for fast type-ahead on title, area, description.
Milestone: a visitor can search, filter, view on the map — all from live data.
2

Listing wizard → database

High priority

The list.html wizard currently runs in demo mode. Make every step write to the database, upload real photos, and submit for review.

Wizard ↔ Supabase — each step saves to listings as a draft. Auto-save on every field change.
Photo upload — drag-and-drop images upload to listing-photos bucket. Reorder, delete, set hero image.
Document upload — title deeds, ownership letters → listing-docs (private bucket). Only owner + admin can view.
Map pin placement — the pin step writes lat/lng + Google Plus Code to the listing. Reverse geocode for area name.
Submit for review — status changes to pending_review. Triggers notify-lead email to admin team.
Seller dashboard — dashboard.html shows the seller's real listings, their status, views and enquiries from the DB.
Milestone: a seller creates a real listing with photos; admin sees it in the review queue.
3

Payments & listing plans

Medium priority

Monetize the platform: sellers choose a plan (Basic free / Verified / Premium) and pay before their listing goes live. checkout.html becomes functional.

Payment provider integration — Wave, QMoney, or Stripe (cards). Start with Wave for local mobile money.
checkout.html → real checkout — plan selection, price display, payment flow. On success: update listing plan + status.
Payment confirmation emails — receipt to seller, notification to admin. Styled like existing email templates.
Webhook handling — payment provider confirms → Edge Function updates listing status.
Admin revenue view — admin.html shows payments received, plan breakdown, revenue per month.
Listing expiry & renewal — listings expire after 90 days. Reminder email 7 days before. Easy renewal via dashboard.
Milestone: a seller pays for a plan; the payment is recorded; the listing goes live.
Prerequisite: Choose a payment provider and set up a merchant account. Wave Money is recommended for local payments; Stripe for international cards.
4

Real-time messaging

Medium priority

messages.html becomes a real chat system. Buyers message agents or sellers; agents respond. Conversations persist and trigger notifications.

Messages table + schema — conversations and messages tables with RLS (only participants can read/write).
Supabase Realtime — new messages appear instantly without refreshing. Typing indicator.
"Message agent" button on property.html creates a conversation tied to that listing. Pre-fills a structured first message.
Unread count in header — the nav shows a badge with unread message count. Real-time update.
Email fallback — if the recipient hasn't read a message within 30 minutes, send an email notification with a deep link to the conversation.
Milestone: buyer and agent can have a real-time conversation about a property.
5

WhatsApp integration

Medium priority

WhatsApp is how The Gambia communicates. Connect it as both a notification channel and a lead source.

WhatsApp Business API — set up via Meta Business (or a BSP like 360dialog/Twilio). Verified business number.
Lead notifications via WhatsApp — when a new lead or viewing request comes in, the assigned agent gets a WhatsApp alert (not just email).
Saved search alerts — users who opt for WhatsApp alerts get new-listing notifications on their phone instead of email.
Listing share via WA — the share button sends a rich message with photo, price and direct link. Already designed in the UI; needs the deep link.
Inbound lead capture — a buyer messages the WhatsApp number → auto-creates a lead in Supabase with the message and phone number.
Milestone: agents receive WhatsApp alerts for leads; buyers get listing alerts on WhatsApp.
Prerequisite: WhatsApp Business API approval + a verified phone number. Apply early — approval can take 1–2 weeks.
6

Title verification workflow

Phase 2 stretch

Turn "Verified Title" from a manual badge into a structured workflow with status tracking, document review, and an audit trail.

Verification schema — title_verifications table: document uploads, status (pending / in_review / approved / rejected), reviewer notes, timestamps.
Seller flow — seller uploads deed + supporting docs from dashboard. Gets status updates via email.
Admin review UI — dedicated view in admin.html: see uploaded docs, approve/reject with notes, mark issues.
Verified badge logic — approved verification → is_verified_title = true → badge appears on listing card and detail page.
Audit trail — every status change logged with timestamp, reviewer, and reason. Visible to admin and seller.
Milestone: a seller submits documents; admin reviews and approves; the Verified badge appears automatically.

Decisions needed before starting

These choices affect sprint 3 and 5. Best decided early.

💳

Payment provider

Wave Money (dominant in Gambia, mobile money) vs Stripe (international cards, diaspora). Recommendation: start with Wave for local sellers, add Stripe later for diaspora buyers.

💬

WhatsApp approach

Official Business API (via Meta or a BSP like 360dialog) vs simple click-to-chat links (no API needed, but no automation). Recommendation: start with click-to-chat, add API in sprint 5.

🔍

Search engine

Meilisearch Cloud (fast, typo-tolerant, hosted) vs Supabase full-text search (free, built-in, less powerful). Recommendation: start with Supabase FTS; migrate to Meilisearch if needed.

💰

Listing pricing

What does each plan cost? Basic (free), Verified (D2,500?), Premium (D5,000?). This needs to be decided before sprint 3 can begin.
