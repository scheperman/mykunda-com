De harvest-knop repareren

"Harvest failed" komt niet uit de knop, maar uit een Edge Function die nooit is uitgerold. Hieronder staat wat er precies mist, wat ik al in de code heb rechtgezet, en de vier stappen die jij nog moet doen — allemaal vanuit de browser.

Duur± 15 minuten
NodigSupabase-dashboard + FTP
CLI nodig?Nee
!

Wat er precies misgaat

Eén hoofdoorzaak, één bijkomend detail.

De functie market-sources bestaat niet op het Supabase-project

De knop doet een POST naar die Edge Function. Er staan wel dertien functies op het project (auth-email, fx-rates, notify-lead, …), maar deze niet. De gateway antwoordt dan met een fout zonder CORS-headers, en dat vertaalt de browser naar de nietszeggende melding "Failed to fetch" — vandaar "Harvest failed".

Detail twee: de frontend bouwde de URL op met de oude host <ref>.functions.supabase.co/market-sources in plaats van het standaardpad <ref>.supabase.co/functions/v1/market-sources. Die oude host werkt nog wel, maar slikt de statuscode in bij fouten. Dat heb ik al gecorrigeerd.

Goed nieuws. De functiecode zelf is compleet en staat al in het project (edge-functions/market-sources/index.ts), inclusief correcte CORS-headers op zowel de preflight als het antwoord. Er is niets te programmeren — alleen uit te rollen.

1

Controleer de tabellen

Supabase-dashboard → SQL Editor → plak en run.

select table_name from information_schema.tables
where table_schema = 'public'
  and table_name in ('market_sources','source_fetch_runs',
                     'external_listings','market_macro','market_area_alias')
order by table_name;

Krijg je vijf rijen terug? Ga door naar stap 2. Krijg je er minder, dan is backend/market-sources.sql nog nooit gedraaid: open dat bestand in het project, plak de volledige inhoud in de SQL Editor en run het één keer. Het is veilig om opnieuw te draaien.

2

Rol de functie uit — zonder CLI

Dit kan volledig in het dashboard; je hoeft niets te installeren.

Ga naar Edge Functions

Supabase-dashboard → linkerbalk → Edge Functions → knop Deploy a new function → kies Via editor.

Naam exact overnemen

Vul in: market-sources. Precies zo, met streepje, kleine letters — de frontend roept die naam aan.

Plak de code

Kopieer hieronder de volledige inhoud van index.ts, wis de voorbeeldcode in de editor en plak dit erin.

Deploy

Klik Deploy function. Na ± 30 seconden staat hij in de lijst met status Active.

…

Liever de CLI? Dan is het één regel vanuit de projectmap:

supabase functions deploy market-sources --no-verify-jwt
Secrets hoef je niet te zetten. De functie gebruikt SUPABASE_URL en SUPABASE_SERVICE_ROLE_KEY; die injecteert Supabase automatisch in elke Edge Function van het eigen project.
3

Zet "Verify JWT" uit

Alleen nodig als je de nachtelijke cron wilt gebruiken.

Open de functie → Settings (of het tandwiel bij de functie) → schakel Verify JWT with legacy secret uit. De harvest vanuit de admin-console werkt met de schakelaar aan óók, want die stuurt jouw sessietoken mee — maar de cronjob doet dat niet en zou dan 401 krijgen.

Let op. De functie is daarmee publiek aanroepbaar. Ze schrijft alleen in eigen markttabellen en leest geen gebruikersdata, dus dat is hier acceptabel — hetzelfde geldt al voor fx-rates.

5

Testen

Open sources.html, log in als admin, ververs hard (Cmd/Ctrl + Shift + R).

Eerst één bron droog draaien

Klik bij een bron op Test. Dat parseert wel, maar schrijft niets weg. Je ziet meteen of de selector rijen vindt.

Dan de echte harvest

Klik Harvest everything now. Verwacht: "Harvest finished." en een verse regel in het runlog eronder.

Controleer het label rechtsboven

Staat er Demo data, dan lukt het lezen van de tabellen niet en is stap 1 nog niet af.

Krijg je alsnog een melding, dan zegt de nieuwe tekst wat er aan de hand is:

6

Nachtelijk laten draaien

Optioneel, pas doen als de handmatige harvest werkt. Vereist pg_cron + pg_net.

select cron.schedule('market-sources-nightly', '20 1 * * *', $$
  select net.http_post(
    url := 'https://jejaerpqltqryqzjvbjp.supabase.co/functions/v1/market-sources',
    headers := '{"Content-Type":"application/json"}'::jsonb,
    body := '{"run":"due"}'::jsonb)
$$);

select cron.schedule('market-index-nightly', '45 2 * * *', $$
  select public.market_dedup();
  select public.market_build_month(current_date);
  select public.market_recompute_derived();
  select public.market_recompute_real();
$$);

De harvest draait om 01:20, de herberekening van de index om 02:45 — bewust uit elkaar, zodat de rollup verse rijen ziet.
